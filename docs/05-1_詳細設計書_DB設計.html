3. テーブル定義

共通方針（基本設計書6.3節）: 主キーは id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY（中間テーブルは複合主キー）。created_at / updated_at は TIMESTAMPTZ NOT NULL DEFAULT now() を全テーブルに付与する（以下の表では省略せず明記する）。全テーブルでRLSを有効にする。コード値カラムはCHECK制約で担保する。

3.7 T-07 message_blocks（発言内の構造化ブロック）

カラム型NULL既定値制約
idBIGINTNOT NULLIDENTITYPRIMARY KEY
message_idBIGINTNOT NULL-FK→messages.id
block_typeTEXTNOT NULL-CHECK IN ('citation','external_system','quote_reference','pending_action','mention')
payloadJSONBNOT NULL-block_typeごとに構造が異なる（下表）
sort_orderINTNOT NULL0同一メッセージ内の表示順
created_atTIMESTAMPTZNOT NULLnow()-

payload構造（本書で確定。フロントはcomponents/blocks/でblock_typeごとに専用コンポーネントを描画）:

// citation（F-20 根拠文書カード。基本設計書8.2節）
{ "doc_title": "運用ドキュメント：デプロイ手順書", "doc_url": "https://drive.google.com/...",
  "folder_path": "開発部 ＞ 運用ドキュメント", "excerpt": "本番デプロイは staging マージ後に..." }

// external_system（F-23 連携先システムの参照結果。基本設計書8.4節）
{ "system_name": "座席予約システム", "summary": "8/22 13-15時 3階エリアに空席5席",
  "detail": { "date": "2026-08-22", "time_range": "13:00-15:00", "area": "3階", "available_seats": 5 } }

// quote_reference（過去のやり取りの参照。要件定義書5.3節・基本設計書8.8節）
{ "message_id": "10245", "sender_display_name": "Kogack AI", "posted_at": "2026-08-10T05:12:00Z",
  "excerpt": "その節は日次バッチの再実行手順をご案内しました。", "anchor": "#msg-10245" }

// pending_action（実行前確認への導線。F-25、S-07）
{ "pending_action_id": "88", "system_name": "座席予約システム", "action_type": "reserve_seat",
  "summary": "8/22 13-15時 3階B-12席の予約" }

// mention（人間への@メンション参照。F-41、基本設計書5.22節）
{ "target_user_id": "15", "display_name_snapshot": "田中 智子" }

'mention'のみ、選択されたメンション1件につき1行（同一メッセージに複数メンションがあれば複数行、sort_orderは本文中の出現順）。表示時はtarget_user_idを解決して現在の表示名・アイコンを描画し、display_name_snapshotは対象アカウントが削除・無効化された場合のフォールバック表示にのみ用いる。

3.15 T-20（欠番）

T-20 recurring_post_recipients はv1.6で新設、個人宛て定期投稿（destination_type='individuals'）の対象外化に伴いv1.9で廃止された。要件定義書3.2節「対象外機能」のとおり、次フェーズで個人宛てを再検討する際に同じIDで再利用する方針とし、欠番のまま採番し直さない（基本設計書6.2節「設計判断」）。

3.17 T-22 read_states（既読状態）

カラム型NULL既定値制約
idBIGINTNOT NULLIDENTITYPRIMARY KEY
user_idBIGINTNOT NULL-FK→users.id
channel_idBIGINTNULL可-FK→channels.id。dm_idと排他（CHECK、T-05と同じパターン）

索引: (user_id, channel_id)・(user_id, dm_id)の部分UNIQUEインデックス（channel_id/dm_idがNULLでない方のみ対象。1利用者につき1チャンネル/DMあたり1行）。メッセージ単位の既読管理はせず「最後に読んだ時刻」のみを保持する簡易な方式（基本設計書6.2節「設計判断」）。行が存在しない参加者は、参加時刻（T-03.joined_at／T-17.joined_at）を既読時刻の代わりに使う。
