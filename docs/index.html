システム概要

社内チャットにAIエージェントが常駐し、質問への回答・依頼への対応・社内システムの操作までを行う社内Webシステム。 AIはチャンネルごとに振る舞い（キャラクタ・参照ドキュメント範囲・スキル・反応の仕方・自動対応範囲）を定義でき、 「総務問い合わせチャンネル＝総務への依頼」といった既存の運用にそのまま乗る。 社内ドキュメントへの質問には質問者の閲覧権限を尊重して回答し（第2層）、 座席予約・e-learningなど社内システムへの登録・変更は実行前の確認を経て行う（第3層）。 Google認証（許可ドメイン: kogasoftware.com）によりアクセスを制御し、既存のSlackと併存する。 技術構成は既存システム（LCC CRM）を踏襲する。

2026年9月末リリース（初期リリース）は、上記の全部ではない。 チャンネル・スレッド・DM・検索・ファイル共有といった土台と、AIのキャラクタ・スキル・反応設定といったチャンネルAIの機能はほぼ全て実装するが、 社内システムへの登録・変更操作（座席予約の参照のみは実装）とスマートフォン対応は対象外とする。対象外の一覧は 要件定義書3.2節 対象外機能 を参照。判定の経緯（何を優先し何を見送ったか）は検討資料にまとめている。 自分たちだけでは決めきれない2件（AI利用コスト上限到達時の挙動、先行運用の対象部署）は要件定義書8.2節 前提条件に「千田氏との別途協議」として明記している。

読み進め方（研修向けガイド）

  1. 要求仕様書 — 「誰が・なぜ・何を」求めているかと、本システムの4層構造を把握する。
  2. 要件定義書 — 要求がどのような要件（機能・画面・権限・非機能）に整理されたか、要求仕様書で未確定だった論点（連携先の優先順位・履歴保持方針等）がどう決着したかを確認する。
  3. 画面モックアップ（完成） — 完成イメージを目で確認する。要件との対応（S-01〜S-08）を意識する。
  4. 基本設計書（完成） — システム全体の構造（構成・DB・API・認証・権限フィルタリングの実現方式・AIエージェント設計）がどう決まったかを理解する。
  5. 詳細設計書（完成） — 実装者として手を動かせるレベルの定義を読む。
  6. 操作マニュアル（未着手） — 設計が実際の画面としてどう動くのかを確認する。
各ドキュメントは共通のID体系で相互参照している: REQ-xx（要求）/ F-xx（機能）/ S-xx（画面）/ T-xx（テーブル）/ A-xx（API）。 上流の要求IDが下流の設計まで追跡できる（トレーサビリティ）ことを確認しながら読むこと。 検討中の判断・比較した代替案は正式な成果物には含めず、検討資料/ に分けて記録している （検討資料/README.md 参照）。
